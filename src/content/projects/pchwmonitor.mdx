<Chapter title="What it is">

PC HW Monitor is an open-source system in two parts: a server on a Windows PC and an Android app. The server reads the hardware and sends one status message per second. The app shows CPU, GPU, integrated GPU, RAM, disk, network, fan and FPS readings.

The real-data server runs on Windows only. It ships as a single EXE with a tray menu that can show a QR code for connecting a phone.

</Chapter>

<Chapter title="Local-first decisions">

By default the phone and the PC talk over the same Wi-Fi network.

<ul class="rows">
  <li>No user account, and no required cloud service.</li>
  <li>The project’s privacy policy states there are no ads, analytics or developer-operated servers.</li>
  <li>History is stored on the phone, covering the last hour.</li>
  <li>Remote access is opt-in. A Cloudflare Tunnel, quick or named, avoids port forwarding, and traffic then passes through Cloudflare’s network.</li>
</ul>

</Chapter>

<Chapter title="Security choices">

An access token is required, and the server generates one if none is supplied. Setup is by QR code or by entering IP, port and token.

TLS is **optional**. With it, the app connects over `wss://`; the server can generate a self-signed certificate, and the app shows a trust dialog. Without it, the connection uses `ws://` and is not encrypted. The app now asks for one-time consent before sending a token over such a connection.

Hardening recorded in the repository history includes:

<ul class="rows">
  <li>rejecting browser origins on the WebSocket endpoint;</li>
  <li>excluding the access token and local history from Android backups;</li>
  <li>timing-safe token comparison, connection limits and rate limiting;</li>
  <li>fixes to TLS trust and certificate pinning.</li>
</ul>

</Chapter>

<Chapter title="Open-source distribution">

The Android app and server are licensed under AGPL-3.0. The Windows EXE also bundles LibreHardwareMonitorLib (AGPL-3.0), cloudflared (Apache-2.0) and PresentMon (MIT).

The app is distributed through Google Play and F-Droid, with builds also on GitHub. Preparing for F-Droid shaped the build: store descriptions were converted to the HTML subset F-Droid accepts, and an Android build-tool dependency block was stripped from APKs to meet its requirements.

It was featured in [Android Weekly #739](https://androidweekly.net/issues/issue-739).

</Chapter>

<Chapter title="What comes next">

The project roadmap lists Linux server support as **planned**. It has not been released. FPS capture is expected to remain Windows-only.

</Chapter>
