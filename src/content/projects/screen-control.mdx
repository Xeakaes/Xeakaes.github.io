<Chapter title="What and why">

The repository is named **computer-use-for-all-agents**. Its documentation also calls the tool Screen Control.

The problem it states: agents can write code and call APIs, but cannot see or touch your desktop. Screen Control is the layer that perceives and acts. It contains no AI model; the connected agent does the reasoning.

The server runs on your own machine. That does not make the connected model local: whatever the agent reads from the screen goes wherever that agent’s model runs.

</Chapter>

<Chapter title="Seeing the screen">

OCR turns on-screen text into data, so a text-only model can follow what is happening. Vision-capable models can request single frames or a live MJPEG stream. A text-based diff reports which areas changed without needing a vision model. OCR is optional; the rest works without it.

On the action side there is mouse input, Unicode-safe typing, window management, and relative mouse movement and held keys for games. Windows also supports virtual desktops and focus-free control of background windows.

</Chapter>

<Chapter title="Safety as the design">

The checks live in the server. The MCP wrapper adds no new powers and goes through the same rules.

### Who may call
Requests need an auth token. The server binds to the local machine by default and rejects untrusted Host headers, which guards against DNS rebinding. Opening it to a network is possible, and the documentation warns that this lets others on the network control the machine.

### Where input may go
When the caller names a target window, the focus guard refuses to type if a different window is in front.

### What is refused
Shortcuts including the Windows key, Ctrl+Alt+Del, Alt+F4 and Shift+Delete are blocked. A list of critical system processes cannot be killed, and the launch endpoint refuses interpreters and shells.

### When something sticks
A watchdog releases held keys and buttons after 30 seconds of inactivity. A release-all endpoint does it immediately.

These measures reduce risk; they do not make giving an agent control of a computer risk-free.

</Chapter>

<Chapter title="Architecture">

An agent connects through REST, or through `mcp_server.py` over stdio or streamable HTTP. The MCP server is a thin wrapper around the Flask API. Behind the API, platform backends handle the operating system.

<ul class="rows">
  <li><strong>Windows 10/11:</strong> the reference backend.</li>
  <li><strong>Linux:</strong> supported with limits in X11 sessions, tested on Linux Mint with Cinnamon. Background input takes focus, there are no virtual desktops, and the cursor cannot be clipped in game mode.</li>
  <li><strong>Wayland:</strong> not supported. The server refuses to start.</li>
  <li><strong>macOS:</strong> a stub that reports itself unavailable.</li>
</ul>

The documentation also notes that speed depends on the agent: model latency and context size set the pace of each perceive, act and verify round.

</Chapter>
