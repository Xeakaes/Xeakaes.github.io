<Chapter title="Read this first">

AeroVision is a project for exploring flow behaviour. **It should not be relied on for engineering decisions**, and this page makes no claim of validated accuracy. The limits are listed below.

<Chapter title="The solver">

<ul class="rows">
  <li><strong>Method:</strong> a collocated finite-volume solver on a voxelized Cartesian grid, using Chorin’s projection method.</li>
  <li><strong>Coupling and advection:</strong> Rhie-Chow interpolation, and a bounded QUICK scheme with a Van Leer limiter.</li>
  <li><strong>Time stepping:</strong> second-order Runge-Kutta (Heun) with a CFL-adaptive step.</li>
  <li><strong>Turbulence:</strong> Spalart-Allmaras, k-epsilon, k-omega SST and Smagorinsky.</li>
</ul>

</Chapter>

<Chapter title="Working with results">

The desktop interface loads STL geometry and shows it in an interactive 3D view. Post-processing covers cut planes, scalar fields, Q-criterion views and a streamline toggle. There are also batch runs, a command-line parameter sweep, saved presets, a comparison mode, and export to CSV, JSON, VTK and PNG. The interface is available in English and Turkish.

</Chapter>

<Chapter title="Three compute paths">

NVIDIA GPUs run through CuPy. Intel and AMD GPUs run through PyOpenCL with custom kernels. Without a usable GPU, the solver falls back to the CPU. The repository includes a self-test that compares GPU and CPU results.

</Chapter>

<Chapter title="Known limits">

<ul class="rows">
  <li>NACA 0012 airfoil lift results are <strong>qualitative only</strong>: on a coarse voxel grid the section is only one or two cells thick.</li>
  <li>On the OpenCL path, k-epsilon, k-omega SST, Smagorinsky and wall functions run on the CPU, so those runs are hybrid.</li>
  <li>GPU speedup depends on the hardware and grid size, and can be small next to a strong CPU.</li>
  <li>The repository includes benchmark scripts for sphere drag and airfoil lift. They are not a substitute for independent validation.</li>
</ul>

</Chapter>
